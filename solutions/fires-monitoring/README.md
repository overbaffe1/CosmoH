# КосмоФАЙР-2 — решение кейса «Двухэтапный мониторинг природных пожаров по данным ДЗЗ»

КосмоХакатон · Красноярск · 18–20 сентября 2026.

Решение состоит из трёх сдаваемых частей, ровно как требует постановка:

| Часть | Что это | Где смотреть |
|---|---|---|
| **AF-модуль** | детекция активного горения по чипу VIIRS 375 м (I1–I5 + вспомогательные слои), бинарная маска | `fires/af.py`, `fires/blobfilter.py` |
| **BS-модуль** | картирование гари и степени поражения 0–3 по паре Sentinel-2 до/после и Sentinel-1 | `fires/bs.py` |
| **`submission.csv`** | RLE-маски по шаблону `sample_submission.csv` | `inference.py`, `fires/submission.py` |
| **Сервис** | информационно-аналитический сервис: REST API, GeoJSON/Shapefile, справка по площадям | `service/` |

Плюс сопутствующие артефакты: подбор параметров (`train.py`), метрика соревнования с абляциями (`evaluate.py`),
отчёт (`docs/report.md`), презентация (`docs/presentation.pdf|html`), тесты (`tests/`, 38 тестов).

## 1. Быстрый старт

```bash
pip install -r requirements.txt

# 1) обязательная команда из постановки (без интерактива, exit code 0)
python inference.py --data-dir /path/to/test --output submission.csv --validate

# 2) подбор параметров на обучающей части (переобучение под реальные данные)
python train.py --data-dir /path/to/train --out weights/weights.json

# 3) метрика соревнования и абляции (для отчёта)
python evaluate.py --data-dir /path/to/train --ablation

# 4) сервис: каталог сцен + REST API + веб-карта
python -m service.catalog --data-dir /path/to/train --out service/catalog.json
uvicorn service.app:app --host 0.0.0.0 --port 8000

# 5) тесты
pytest tests -q
```

Если реального набора под рукой нет — работает синтетический стенд:

```bash
python -m fires.synthetic /tmp/firesdata/dev2 --n-af 60 --n-bs 30 --seed 11 --clean
python train.py     --data-dir /tmp/firesdata/dev2 --out weights/weights.json
python evaluate.py  --data-dir /tmp/firesdata/dev2 --weights weights/weights.json \
                    --blob-filter weights/blob_filter.pkl --ablation
python inference.py --data-dir /tmp/firesdata/dev2 --output /tmp/submission.csv --validate
```

**Первое, что нужно сделать на реальных данных** — диагностика раскладки: организаторы не публикуют имена файлов,
поэтому `fires/chips.py` распознаёт каналы по шаблонам, а команда печатает, что именно найдено:

```bash
python -m fires.chips --data-dir /path/to/train
```

## 2. Что именно делает решение

### 2.1. AF: детекция активного горения

1. **Скрининг.** Исключаются вода (WorldCover 80), невалидные пиксели, облака. Солнечный блик не выбрасывается
   (внутри блика может быть настоящий очаг), а переводится в «подозрительный» режим: нужен ΔT выше порога не менее
   чем на 9 K либо I4 ≥ 335 K.
2. **Абсолютные тесты.** I4 ≥ 367 K (насыщение канала, безусловное горение), I4 ≥ 360 K (очень яркий очаг).
3. **Контекстный тест.** Кандидат — пиксель, у которого I4 выше фона в окне 71×71 на `k·σ` **и** ΔT = I4 − I5 больше
   порога (15 K днём, 10 K ночью). Фон считается по пикселям, не являющимся кандидатами, — как в операционном
   продукте VIIRS 375 м (Schroeder et al., 2014).
4. **Отсев техногенных источников.** Застройка и промплощадки (WorldCover 50): остаются только очаги крупнее 4 px
   и заметно сильнее типичного факела; одиночные слабые пиксели на пашне и открытой почве убираются.
5. **Классификатор очагов (`fires/blobfilter.py`).** Кандидаты (мягкие пороги + результат правил) собираются в
   блобы 8-связностью и морфологическим закрытием; для каждого блоба считаются 23 признака (площадь, заполнение
   bbox, статистики I4/ΔT/I1/I3, доля блика, состав типов покрова, отношение периметра к площади, доля слабых
   тёплых пикселей вокруг) и решение принимает `HistGradientBoostingClassifier`.

   Это ключевой механизм: по одному пикселю газовый факел неотличим от пожара (I4 насыщен, ΔT даже выше), а по
   форме, площади и окружению — отличается. Абляция показывает вклад **+0.067 Score** (F1_af 0.755 → 0.948).

### 2.2. BS: гарь и степень поражения

1. `NBR = (B8A − B12)/(B8A + B12)`, `dNBR = NBR_pre − NBR_post`, `rdNBR = dNBR/√|NBR_pre|`.
2. Маскировка по SCL (облака, тени, снег, вода) и слою валидности.
3. Пороги dNBR **по типам покрова**: лес/кустарник — 0.10 / 0.27 / 0.66 (шкала USGS), степь и пойма —
   0.04 / 0.12 / 0.28, пашня и открытая почва — 0.05 / 0.12 / 0.26; застройка и снег не картируются.
   Без этой адаптации Score падает с 0.95 до 0.68 (абляция).
4. **Sentinel-1**: пиксели под облаком/тенью восстанавливаются по падению VH — эквивалентный
   `dNBR = −ΔVH / чувствительность` (лес ≈ 3 дБ на единицу dNBR, остальные покровы ≈ 1.5), порог срабатывания
   1 дБ, класс берётся по универсальной шкале USGS. Вариант выбирается на двух фолдах по событиям пожара.
5. Постобработка: заполнение внутренних «дыр», удаление контуров меньше 6 px.

### 2.3. Ответ и его валидация

`inference.py` пишет CSV строго по шаблону: `chip_id,class_id,rle`; RLE — пары «начало длина» с 1, по возрастанию,
серии не пересекаются и **не соприкасаются** (соседние серии склеиваются), пустая строка допустима.
`--validate` проверяет: совпадение набора пар с `sample_submission.csv`, синтаксис RLE, выход за границы чипа и
пересечение масок разных классов внутри чипа.

## 3. Результаты

Локальный стенд (синтетический набор, воспроизводящий раскладку и артефакты реальных данных:
облачность, тени, газовые факелы, блик, разнородный фон).

| Компонента | Значение |
|---|---|
| **Score** (0.35·F1_af + 0.35·IoU_burn + 0.30·mIoU_sev) | **0.9497** |
| F1_af | 0.9476 (tp 950, fp 0, fn 105) |
| IoU_burn | 0.9735 |
| mIoU_sev (классы 1/2/3) | 0.9243 (0.885 / 0.906 / 0.982) |
| Скорость `inference.py` (180 чипов) | 5.1 с при пороге 30 с |
| Повторный запуск | побайтово одинаковый CSV (детерминизм) |

Абляции (`python evaluate.py --data-dir … --ablation`, набор dev2, 180 чипов):

| Вариант | Score | F1_af | IoU_burn | mIoU_sev |
|---|---|---|---|---|
| Итоговая конфигурация | 0.9497 | 0.9476 | 0.9735 | 0.9243 |
| AF: только правила (без классификатора очагов) | 0.8822 | 0.7549 | 0.9735 | 0.9243 |
| AF: без пиксельного гейта в блобе | 0.9269 | 0.8825 | 0.9735 | 0.9243 |
| AF: порог классификатора 0.95 вместо подобранного | 0.9482 | 0.9434 | 0.9735 | 0.9243 |
| AF: кандидаты только по мягким порогам | 0.9497 | 0.9476 | 0.9735 | 0.9243 |
| BS: без порогов по типу покрова (только USGS) | 0.6828 | 0.9476 | 0.7810 | 0.2595 |
| BS: без Sentinel-1 | 0.9509 | 0.9476 | 0.9579 | 0.9465 |
| BS: SAR без восстановления под облаком | 0.9444 | 0.9476 | 0.9579 | 0.9247 |
| BS: без заполнения дыр | 0.9388 | 0.9476 | 0.9539 | 0.9109 |

Интерпретация: классификатор очагов и пороги по типам покрова — два механизма, которые дают основной прирост;
Sentinel-1 улучшает полноту гари в облачных сценах (IoU_burn +0.016) при небольшой потере по классам на синтетике
(на реальных данных вариант по SAR выбирается автоматически на двух фолдах).

> Все числа получены на синтетическом стенде: реальный набор с Яндекс.Диска недоступен из среды разработки
> (SSL-ошибка сети). Стенд воспроизводится командой `python -m fires.synthetic`, поэтому результаты проверяемы.

## 4. Сервис

```bash
python -m service.catalog --data-dir /path/to/train --out service/catalog.json
CATALOG_PATH=service/catalog.json uvicorn service.app:app --host 0.0.0.0 --port 8000
```

| Метод | Назначение |
|---|---|
| `GET /` | веб-карта: контуры гари по степеням + термоточки, справка; без CDN и тайлов |
| `GET /api/health` | состояние каталога |
| `GET /api/thermopoints?bbox=…&date_from=…&date_to=…` | термоточки за период (GeoJSON) |
| `GET /api/burn-contours?severity=2,3` | контуры гари с атрибутами id, severity, area_ha, chip_id, date |
| `GET /api/report?format=json|csv` | площадь гари в га, распределение по трём степеням, число контуров |
| `POST /api/query` | территория (полигон или bbox) + даты → точки, контуры и справка одним вызовом |
| `GET /api/export/contours.geojson` / `.shp` | выгрузка контуров (GeoJSON; Shapefile — zip с .shp/.shx/.dbf/.prj) |
| `GET /api/catalog/reload` | перечитать каталог без перезапуска |

Геопривязка: если организаторы дают координаты (`chips_geo.csv` с полями `chip_id,origin_lon,origin_lat,gsd,date,kind`),
каталог строится в географическом режиме. Если привязка скрыта (как в тестовой части кейса), каталог собирается в
**демонстрационном** режиме — это явно видно в `GET /api/report` (`catalog_mode`) и в шапке веб-карты.
Ответ submission от режима каталога не зависит.

## 6. Воспроизводимость и ограничения

* Все источники случайности зафиксированы (`SEED = 20260918`), обучение воспроизводится командой `train.py`.
* Инференс детерминирован: повторный прогон даёт побайтово одинаковый `submission.csv`.
* Разделение train/val — по `fire_event_id`, как у организаторов: чипы одного пожара не попадают в разные части.
* Метрика считается тем же способом, что и у организаторов: микро-агрегация по пулу пикселей, пустой класс = 1.
* Открытые библиотеки: numpy, scipy, scikit-learn, tifffile, FastAPI, uvicorn, pydantic, pyshp, matplotlib, pytest.
  Закрытых моделей и внешних API нет; FIRMS/MCD64A1 не используются.
* Ограничения: реальные данные недоступны из среды разработки (все числа — на синтетическом стенде); под облаками
  точность ограничена физикой (оптики там нет); классы 1 и 2 в степи различаются слабо.
