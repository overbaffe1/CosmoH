## 3. Кейсы

### Красноярск

**К1. «Оперативный мониторинг лесных пожаров»** (тип: Data/ДЗЗ + веб-сервис или API)
Два этапа: (1) поиск очагов горения по тепловым каналам MODIS/VIIRS/Landsat с отсевом ложных
срабатываний; (2) картирование гарей по Sentinel-2 с оценкой степени поражения леса.
Результат: сервис/API с картой очагов и справкой о площади гари в гектарах.
На странице кейса указана **метрика** → вероятна автоматизированная проверка.

*Плюсы:* ясное ТЗ, объективная метрика, бесплатные данные (FIRMS, Sentinel-2, Landsat), быстрый
прототип (rasterio/GDAL + geopandas + FastAPI + MapLibre), эффектное демо (карта + алерты + га).
*Минусы:* самая «модная» тема — высокая конкуренция среди ML/ДЗЗ-участников (в чате Красноярска
несколько человек с опытом Landsat-8/9/Sentinel-2 и FIRMS); легко получить плохую метрику
(облачность, тайлинг, сезонность, ложные срабатывания). Денежный приз под вопросом.

**К2. «Зелёные инвестиции»** (тип: аналитика/данные + обоснование инвестиционных решений)
Исследовать, как данные о состоянии лесных территорий используются для оценки климатического и
экономического потенциала; предложить цифровое решение для анализа изменений, связанных с
углеродным балансом, и применения результатов в инвестиционных решениях.

*Плюсы:* меньше «хардкод-ML» конкурентов; победа зависит от связки «данные → углеродная модель →
экономика → интерфейс для ЛПР». Если у команды есть финансист/аналитик — реальное преимущество:
большинство сдаёт дашборд без экономики. Простор для wow-фич: MRV-пайплайн (биомасса/AGB, Sentinel-2,
GEDI/GlobBiomass), расчёт пула углерода, стоимость 1 т CO₂, сценарии, NPV/IRR, реестр углеродных единиц.
*Минусы:* субъективная оценка; надо уверенно говорить про таксацию, углеродные единицы и 141-ФЗ/климатические
проекты; без эксперта легко «поплыть» на защите.

### Санкт-Петербург

**К3. «Орбитальный риск»** (тип: исследование + техническое решение)
Угрозы для космонавта в открытом космосе: солнечная и геомагнитная активность, радиация и др.
Надо исследовать ключевые угрозы и разработать техническое решение, связанное с их анализом.

*Плюсы:* редкая тема → конкурентов заметно меньше (в чате направление упомянул буквально один человек);
отличная почва для прототипа: данные космической погоды (GOES/DSCOVR/ACE, Kp/Dst, F10.7, потоки
протонов), оценка дозы/риска, индекс риска ВКД, окна безопасности, алерты, интеграция с орбитой МКС.
Хорошо продаётся жюри как «мы сделали не картинку, а систему поддержки решения».
*Минусы:* нужны предметные знания (SEP/GLE, радиационные пояса) — ошибки видны эксперту;
риск уйти в теорию и не собрать работающий прототип.

**К4. «Топливный космоконтур 2035»** (тип: управленческо-инженерный кейс)
Спроектировать систему снабжения орбитального топливного узла на 2035–2040: подобрать сочетание
долгосрочных, гибких, аварийных и перспективных лунных источников, рассчитать резервы, решить,
во что вкладываться заранее, а что держать опционом; выстроить контрактную, финансовую и риск-архитектуру.

*Плюсы:* низкая конкуренция среди «кодеров»; выигрывает системное мышление: модель лунного льда/ISRU,
криогенное хранение и перелив (ZBO), танкеры/депо, энергетика, NPV/ROIC, real options, контракты
(take-or-pay, cost-plus, опционы), риски и дорожная карта. Сильный ход — количественная модель
(Монте-Карло + real options) и дашборд-симулятор вместо текстовой презентации.
*Минусы:* без цифр превращается в эссе; жюри может спросить про массы, Δv, энергетику, затраты на криогенику.

  Команда Вероники Тазовой ищет GIS/ДЗЗ/ML-человека под «зелёный» кейс — конкуренция там тоже есть,
  но ниже.

  в Благовещенске «денежный» кейс — гидрология, «спутники» — спецноминация. Для Красноярска, какой из
  двух кейсов денежный, в чате так и не ответили → **спросить на брифинге**.
* **СПб:** офлайн-места разобраны ещё до старта; много «свободных агентов» с сильным бэкграундом
  (ML/LLM, фронтенд, продуктовые аналитики), часть команд добирает людей прямо 17–18.09.
* **Благовещенск:** хакатон переносился (был скандал), новые даты 21–23.09, кейсы и данные
  переделаны и выдаются **только на открытии**; репозитории — на GitVerse (нужен username в профиле).
  Часть команд с прошлых дат имела доступ к старым материалам — организаторы заявили, что
  преимущества не будет.
* Полезные замечания участников: «выбор кейса — в любое время, дедлайн = стоп-код»;
  «можно взять 2 задачи, но защищать только одно решение»; по прошлому опыту кейс с пожарами
  «интересный и сложный, метрики получить тяжело».

## 5. Рекомендация по выбору кейса

### Вариант A — если ядро команды ML/CV/ДЗЗ (рекомендую по умолчанию)

| Город | Кейс | Почему |
|---|---|---|
| Красноярск | **«Оперативный мониторинг лесных пожаров»** | Ваш профиль — целевой для этого кейса; метрика объективна, победа = качество пайплайна + рабочий сервис. Оба этапа (hotspots + гари) дают больше «объёма» решения, чем у конкурентов с одной моделью |
| Санкт-Петербург | **«Орбитальный риск»** | Тот же тип работы (данные → модель → риск-индекс → алерты/карта), но конкурентов в СПб меньше; редкая предметка даёт вау-эффект и преимущество в глазах жюри |

Синергия: один архитектурный каркас на оба города — слой данных → расчёт → индекс/оценка →
API (FastAPI) → дашборд с картой. Разные данные и предметка, разный код решения (см. риски правил).

### Вариант B — если сильнее продукт/аналитика/экономика (мало ML-часов)

| Город | Кейс | Почему |
|---|---|---|
| Красноярск | **«Зелёные инвестиции»** | Выигрывает тот, кто свяжет лесные данные с углеродным пулом и деньгами; чистая ML-гонка не нужна |
| Санкт-Петербург | **«Топливный космоконтур 2035»** | Управленческо-финансовый кейс: количественная модель + real options + контрактная архитектура бьют «текстовые» презентации конкурентов |

### Чего избегать

* Не брать **два кейса в одном городе** — защищать можно только одно решение, силы уйдут впустую.
* Не гнать один и тот же код в два зачёта: пп. 9.1/9.6/11.1 (решение должно быть разработано в рамках
  хакатона; сокрытие заранее созданного = дисквалификация). Общие библиотеки/шаблоны — ок, фиксируйте
  историю коммитов в обоих репозиториях.
* Помнить про п. 6.8: топ-4 в СПб/Красноярске закрывает участие в остальных окружных (в т.ч. Благовещенске 21–23.09).
* Помнить про таймзону Красноярска в расписании (МСК vs МСК+4) — риск опоздать со стоп-кодом.
